# 错误成因表（收到判题结果后按需读取）

> 用途：用户把洛谷评测结果（AC/WA/TLE/MLE/RE/CE/PE）回报后，按「错误类型 → 常见原因类别 → 引导方向」给引导。
> 关键规则：**原因类别的讲解每个错误类型只给一次**（讲过的不再重复系统讲，除非用户再次请求）；同类再次出错时，针对该次具体实例引导，不复述整段原因。
> CE 是一等公民：本表「读报错」流程对两种语言都适用。

---

## CE — 编译错误（Compile Error）
- **原因类别**：代码没过编译，根本没运行。新手最常见。多为语法/拼写/缺分号括号/类型不匹配/用了未声明的标识符。
- **引导方向（教读报错，不替改）**：
  1. 让用户把**完整报错文本**贴来（两语言的报错都要能读）。
  2. 教用户看报错里的**文件名 + 行号 + 错误类型/说明**，先定位到第一处错误（后面常是连锁假报）。
  3. 引导用户自查该行附近：分号、括号配对、拼写、类型、声明。
  4. **只在用户明确求助时才给具体修法**；否则指方向。
- **讲一次**：报错行号/连锁假报/常见语法点，讲一次后不再重复。

## RE — 运行时错误（Runtime Error）
- **原因类别**：能编译能跑，但跑起来崩溃。多为数组越界、除零、空指针/空引用、递归无终止/太深、栈溢出。
- **引导方向**：先问「第几个测试点/什么输入崩的」→ 怀疑下标边界（0 还是 n-1）→ 除零 → 递归终止条件 → 数组开多大。让用户**打印关键变量/边界值**来定位（指令式教打印调试）。

## WA — 答案错误（Wrong Answer）
- **原因类别**：能跑但输出不对。多为逻辑错、边界处理（off-by-one）、初始化、比较/赋值混淆、特殊输入没考虑。
- **引导方向**：构造最小可复现样例 → 让用户**手算一遍期望 vs 实际** → 查边界（空、单元素、最大值）→ 查 `=`/`==`、循环终止条件。不直接给正确代码。

## TLE — 超时（Time Limit Exceeded）
- **原因类别**：算法太慢（复杂度太高）或死循环。多为用了 O(n²) 解 O(n log n) 的问题、或循环条件写错停不下来。
- **引导方向**：先排除死循环（循环变量是否更新）→ 再估复杂度（n 多大、循环几层）→ 引导 toward 更优算法（二分/贪心/前缀和/哈希等，按当前层级）。

## MLE — 超内存（Memory Limit Exceeded）
- **原因类别**：数据结构开太大（如数组开成 1e9）、递归太深、不必要的大拷贝。
- **引导方向**：算一下数组/容器最大可能占用 → 是否开了固定大数组 → 递归深度 → 改用按需分配（vector 等）。

## PE — 格式错误（Presentation Error）
- **原因类别**：内容对了但输出格式不符：多/少空格、换行、行尾多余空格、大小写。
- **引导方向**：对照题面输出格式 → 逐字符比对空格/换行 → 特别注意行尾与末尾换行。

## OLE — 输出超限（Output Limit Exceeded）
- **原因类别**：输出了远多于预期的内容，多为循环失控导致刷屏。
- **引导方向**：查循环是否提前退出、是否输出了调试残留。

## 读报错（CE 专用，两语言通用流程）
1. 取**第一处**错误（编译通常一次报第一个，修完再编译会暴露下一个）。
2. 看**行号**，跳到该行；若行号指向 `}` 或末尾，真实错误常在上方。
3. 看错误**类型/关键词**（undeclared/expected/size/ambiguous…）。
4. 围绕该行自查：拼写、分号、括号、类型、声明顺序、头文件/import。
5. 引导用户改一处 → 重新编译 → 再看下一个报错。
